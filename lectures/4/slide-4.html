Content Security Policy

Найпотужніший захист від XSS

📜 script-src 'self' — лише скрипти з того ж домену, блокує inline
🎨 style-src — контроль CSS, захист від витоку даних через CSS (CSS-exfiltration)
🌐 connect-src — whitelist доменів для AJAX/WebSocket
🖼️ frame-ancestors 'none' — захист від clickjacking
📊 report-to — браузер надсилає звіти про порушення CSP

Strict CSP — nonce-based

Whitelist доменів легко обходиться!

❌
CSP з білим списком (Whitelist)
script-src cdn.com *.google.com
Обхід через JSONP-точки доступу
Обхід пісочниці Angular
Будь-який дозволений хост
✅
Nonce-based CSP
script-src 'nonce-abc123'
Новий nonce кожен запит
Inline скрипт без nonce — блок
XSS payload не має nonce

Google рекомендує strict nonce-based CSP. CSP на основі білих списків (whitelist) обходиться у 94% випадків.

Subresource Integrity (SRI)

Перевірка цілісності зовнішніх скриптів

1
Хеш
Обчислюється SHA-384 хеш скрипту
2
integrity=""
Хеш додається до тегу script
3
Перевірка
Браузер порівнює хеш
4
Блокування
Якщо не збігається → скрипт не виконується

Захист від Magecart: якщо CDN скомпрометовано і скрипт змінено — SRI заблокує виконання.

Кодування виводу (Output Encoding)

Основний захист від XSS

📄
HTML-кодування (HTML Encoding)
< → &lt; > → &gt; Для тексту в HTML
🏷️
Кодування атрибутів (Attribute Encoding)
+ лапки " ' для HTML-атрибутів
⚙️
JS-кодування (JS Encoding)
\uXXXX для даних всередині JavaScript
🔗
URL-кодування (URL Encoding)
%XX для URL-параметрів

Екранувати при ВИВОДІ, не при введенні. Дані зберігаються чистими, кодування — за контекстом.

Trusted Types

Браузерний захист від DOM XSS

🔒 Блокує рядки у небезпечних sinks: innerHTML, document.write, eval
✅ Дозволяє лише «довірені» об'єкти через явну санітизацію
🏭 Фабрика політик (Policy factory) — централізована точка санітизації (DOMPurify)
📋 CSP: require-trusted-types-for 'script' — активація через header

Google використовує Trusted Types внутрішньо. Зменшує DOM XSS на 60%+ у великих додатках.

Комплекс безпечних заголовків (Secure Headers)

Обов'язкові заголовки для фінансового додатку

🛡️ Content-Security-Policy — захист від XSS та data injection
📄 X-Content-Type-Options: nosniff — запобігання MIME-sniffing
🖼️ X-Frame-Options: DENY — захист від clickjacking
🔐 Strict-Transport-Security — примусовий HTTPS (HSTS)
🔗 Referrer-Policy — контроль витоку URL при навігації
🎤 Permissions-Policy — обмеження camera, microphone, geolocation

CSP Policy Builder

Покрокове створення CSP для фінансового додатку

1
Базова політика
default-src 'none' — заборонити все за замовчуванням
2
Скрипти
script-src 'nonce-{random}' 'strict-dynamic' — nonce для кожного запиту
3
Стилі та ресурси
style-src 'self'; img-src 'self' data:; font-src 'self'
4
Мережеві з'єднання
connect-src 'self' api.bank.com — тільки власні API
5
Фрейми та звітність
frame-ancestors 'none'; report-uri /csp-report

Починайте з Content-Security-Policy-Report-Only для тестування, потім переключіть на примусове виконання (enforcement).

DOMPurify — санітизація HTML

Безпечна обробка користувацького HTML-контенту

❌
Небезпечно
element.innerHTML = userInput;

// XSS: userInput може містити
// <img onerror=alert(1)>
// <svg onload=steal()>
✅
Безпечно
element.innerHTML =
  DOMPurify.sanitize(userInput);

// Видаляє: onerror, onload,
// script, iframe, event handlers

DOMPurify — стандарт індустрії. 10KB gzipped, 100+ правил, підтримується Google, Mozilla, Cure53.

Trusted Types API

Нативний браузерний захист від DOM XSS

🔒 Принцип: блокує присвоєння рядків у небезпечні sinks (innerHTML, eval, document.write)
🏭 Policy: trustedTypes.createPolicy('sanitize', {createHTML: input => DOMPurify.sanitize(input)})
🛡️ CSP активація: require-trusted-types-for 'script'; trusted-types sanitize
📊 Результат Google: зменшення DOM XSS на 60%+ у Gmail, Google Drive, YouTube

Ключові висновки

1️⃣ CSP nonce-based — найефективніший захист від XSS
