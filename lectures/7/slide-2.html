EMV-чіп
Унікальний криптограм
Неможливо клонувати

Перенесення відповідальності: якщо термінал не підтримує чіп — відповідальність за шахрайство на торговці.

Токенізація платежів

1
PAN → Vault
Реальний номер у захищеному сховищі
2
Token видається
Унікальний токен замість PAN
3
Merchant працює
Зберігає та використовує лише токен
4
Детокенізація (Detokenization)
Лише при оплаті — PAN повертається

Токенізація (Tokenization) зменшує обсяг вимог PCI DSS: системи з токенами не підпадають під повні вимоги.

3D Secure 2.0

Автентифікація онлайн-платежів

📱 Push у банк-додаток — підтвердження покупки одним натисканням
📊 На основі ризику (Risk-based) — 150+ параметрів: пристрій, IP, історія, торговець
✨ Безперешкодний потік (Frictionless Flow) — 95% низько-ризикових транзакцій без додаткової перевірки
🔄 Перенесення відповідальності (Liability Shift) — при 3DS шахрайство → відповідальність на банку-емітенті

PSD2 SCA вимагає 3DS2 для онлайн-платежів у ЄС. Україна рухається до аналогічних вимог.

Наскрізне шифрування (P2PE)

Point-to-Point Encryption — від термінала до хоста

🔐
Шифрування при зчитуванні
Дані шифруються в момент зчитування на терміналі
🔒
Ніколи у відкритому вигляді
Дані НІКОЛИ не з'являються у відкритому вигляді в мережі
📉
Зменшення обсягу вимог
Значне зменшення обсягу вимог PCI DSS для торговця
🛡️
Захист від шкідливого ПЗ
Шкідливе ПЗ на POS не може перехопити дані — вже зашифровані

Ланцюжок карткової транзакції

1
Власник картки (Cardholder)
POS / Online → зчитування картки
2
Банк-еквайєр (Acquirer)
Банк торговця приймає транзакцію
3
Карткова мережа (Card Network)
Visa / Mastercard маршрутизує
4
Банк-емітент (Issuer)
Банк клієнта авторизує / відхиляє

Кожна ланка повинна відповідати PCI DSS. Компрометація будь-якої = витік карткових даних.

Потік EMV-транзакції з чіпом

Покрокова обробка чіпової транзакції

1
Вибір додатка
Термінал читає AID з чіпа, обирає платіжний додаток (Visa/MC)
2
Автентифікація даних
SDA/DDA/CDA — перевірка автентичності даних картки через RSA-підписи
3
Верифікація власника
PIN Online / PIN Offline / Підпис / Без CVM (безконтактні малі суми)
4
Управління ризиками
Чіп перевіряє: floor limit, velocity, offline counter. Рішення: approve/decline/go online
5
Генерація ARQC
Чіп генерує унікальний криптограм запиту (Application Request Cryptogram) з даних транзакції

Архітектура токенізації

Детальна схема компонентів

🏦
Постачальник токен-сервісу (TSP)
Visa VTS / MC MDES — генерація, зберігання маппінгу token-PAN, управління життєвим циклом
🗄️
Токен-сховище (Token Vault)
HSM-захищене сховище. PAN зашифрований AES-256. Доступ лише через API з mTLS
🔄
Типи токенів (Token Types)
Платіжний токен (для транзакцій), токен безпеки (для зберігання), токен пристрою (прив'язаний до пристрою)
📋
Доменне обмеження (Domain Restriction)
Токен обмежений: конкретний merchant, канал (e-com/POS), пристрій. Викрадений токен — марний

Формат токена: 13-19 цифр, проходить Luhn check, але BIN-діапазон не перетинається з реальними картками.

3D Secure 2.0 — потік автентифікації

Покрокова взаємодія компонентів

1
3DS Method
Торговець збирає дані пристрою (відбиток браузера, IP) через прихований iframe
2
AReq → DS → ACS
3DS Server надсилає Authentication Request через Directory Server до банку-емітента (ACS)
3
Оцінка ризиків
ACS аналізує 150+ параметрів: пристрій, історія, сума, ризик торговця, геолокація
4
Безперешкодний / Перевірка
Низький ризик → без додаткових кроків. Високий ризик → перевірка (OTP, push, біометрія)
5
ARes + Auth Token
Результат повертається торговцю. CAVV/AAV токен додається до авторизаційного запиту

P2PE — ієрархія ключів

Управління ключами у наскрізному шифруванні

🔑 Головний ключ (Master Key) — зберігається в HSM дешифрувального хоста. Ніколи не покидає HSM
🔑 Ключ шифрування ключів (KEK) — шифрує робочі ключі при передачі на термінал. Захищений MK
🔑 Базовий ключ деривації (BDK) — основа для DUKPT-деривації. Кожний термінал має унікальний початковий ключ
🔑 Сесійний ключ (Session Key) — одноразовий ключ для кожної транзакції, деривований через DUKPT-алгоритм
🔒 DUKPT — унікальний похідний ключ на транзакцію. 1M+ унікальних ключів з одного BDK. Компрометація SK не розкриває BDK

PCI P2PE v3.0 вимагає: tamper-resistant POI, HSM для дешифрування, сертифікований KIF для ін'єкції ключів.

🛡️

Ключові висновки

1️⃣ EMV — dynamic crypto замість static data, -76% fraud
2️⃣ Токенізація (Tokenization) — торговець ніколи не бачить реальний PAN
3️⃣ 3DS 2.0 — автентифікація на основі ризику, безперешкодний потік для 95% транзакцій
4️⃣ P2PE — шифрування від терміналу, шкідливе ПЗ не загрожує
