80% атак використовують бічне переміщення (Lateral Movement) після початкового проникнення. Периметр вже не рятує.

4 принципи Zero Trust

🔍
Ніколи не довіряй (Never Trust)
Кожен запит перевіряється незалежно від джерела — внутрішня мережа чи інтернет
🔐
Найменші привілеї (Least Privilege)
Мінімально необхідні права. Доступ «точно вчасно» (Just-in-Time) замість постійних привілеїв
🧱
Мікросегментація
Ізоляція сегментів мережі. Компрометація одного не дає доступ до інших
🎯
Припущення компрометації (Assume Breach)
Проєктуємо так, ніби компрометація вже сталась. Моніторинг та детекція 24/7

BeyondCorp — Zero Trust від Google

Відповідь на Operation Aurora (2009-2010)

🌍 Всі сервіси через інтернет — немає «внутрішньої мережі»
📱 Довіра до пристрою (Device Trust) — перевірка стану пристрою (шифрування, антивірус, патчі)
👤 Контекст користувача (User Context) — хто, звідки, в який час, яка операція
📊 Безперервна оцінка (Continuous Assessment) — рівень довіри перераховується постійно

Google повністю відмовився від VPN. 100,000+ співробітників працюють за моделлю BeyondCorp.

Мікросегментація у FinTech

Ізоляція критичних систем

💳
Платіжна зона (Payment Zone)
SWIFT, картковий процесинг, HSM
👥
Дані клієнтів (Customer Data)
PII, KYC-дані, історія транзакцій
🖥️

Email, офісні системи, HR

Правило: компрометація email-сервера НЕ МОЖЕ дати доступ до платіжних систем. Різні сегменти, різні credentials, різні політики.

Zero Trust для SWIFT-оператора

Приклад перевірок при кожній операції

✅ JWT-токен — валідний, не прострочений, правильний issuer
✅ Роль — користувач має роль swift_operator
✅ Пристрій — корпоративний ноутбук, диск зашифрований, AV оновлений
✅ Час — робочі години (09:00-18:00)
✅ Геолокація — Україна (не з підозрілої країни)
✅ Поведінка — сума транзакції в межах типової для цього оператора

Модель BeyondCorp у деталях

Архітектурні компоненти моделі Google

📡
Проксі доступу (Access Proxy)
Єдина точка входу до всіх внутрішніх сервісів через HTTPS. Замінює VPN повністю
📋
Інвентаризація пристроїв (Device Inventory)
Реєстр усіх пристроїв з рівнем довіри: стан ОС, шифрування, патчі безпеки
🧠
Механізм контролю доступу (Access Control Engine)
Динамічний механізм рішень: аналіз контексту користувача та пристрою в реальному часі
🔄
Оцінка довіри (Trust Score)
Числовий рівень довіри, що перераховується постійно на основі поведінки та контексту

BeyondCorp доводить: корпоративна мережа не є безпечнішою за інтернет. Захищайте ресурси, а не периметр.

Кроки впровадження Zero Trust

Покроковий план трансформації

1
Інвентаризація
Каталог усіх ресурсів, користувачів, пристроїв та потоків даних
2
Ідентифікація
Впровадження IdP (Okta, Azure AD) з MFA для всіх
3
Сегментація
Розділення мережі на мікросегменти з окремими політиками
4
Політики
Визначення правил доступу: хто, що, звідки, коли
5
Моніторинг
SIEM + UEBA для безперервного аналізу поведінки
6
Автоматизація
Автоматичне реагування на аномалії та інциденти

Мікросегментація: приклад банку

Практична ізоляція зон у фінансовій системі

🔴 Червона зона (PCI DSS) — картковий процесинг, HSM, токенізація. Доступ тільки з PEP через мережу сервісів
🟠 Помаранчева зона (KYC/AML) — верифікація клієнтів, моніторинг транзакцій. Ізоляція PII-даних
🔵 Синя зона (Core Banking) — рахунки, депозити, кредити. Мережеві політики дозволяють тільки API Gateway
🟢 Зелена зона (DMZ) — мобільний додаток, веб-портал. Публічний доступ через WAF та CDN
4
зони безпеки
0
прямих з'єднань між зонами

Безпека, орієнтована на ідентичність (Identity-Centric Security)

Ідентичність як новий периметр

👤
Користувачі
MFA, passwordless, biometric. Кожна дія прив'язана до верифікованої особи
📱
Пристрої
MDM-реєстрація, health check, compliance scoring при кожному запиті
🤖
Сервіси
SPIFFE/SPIRE — стандарт ідентичності для мікросервісів з автоматичною ротацією

SPIFFE (Secure Production Identity Framework) надає кожному сервісу криптографічну ідентичність: spiffe://bank.ua/payment-service. Це основа Zero Trust для мікросервісів.

Ключові висновки

1️⃣ Периметрова модель застаріла — хмари, віддалена робота, SaaS зруйнували традиційний підхід
2️⃣ Never Trust, Always Verify — кожен запит перевіряється
3️⃣ Мікросегментація — ізоляція критичних систем обмежує радіус ураження (blast radius)
4️⃣ Контекст = ключ — хто, що, звідки, коли, як — все враховується
