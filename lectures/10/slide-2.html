Чому смарт-контракти вразливі?

🔒 Незмінність (Immutable) — після розгортання код НЕ можна виправити «патчем» (без proxy)
👁️ Публічність (Public) — код відкритий, зловмисник бачить та вивчає вразливості
💰 Цінність (Value) — контракти зберігають мільярди доларів, мотивація для атак максимальна
⚡ Композиційність (Composability) — «грошові лего»: атака на один контракт = каскад збитків

Повторний вхід (Reentrancy Attack)

1
Виведення (Withdraw)
Зловмисник запитує вивід коштів з контракту
2
Зворотний виклик (Callback)
Контракт надсилає ETH — зловмисний fallback автоматично виконується
3
Повторний вхід (Re-enter)
Fallback знову викликає withdraw() — баланс ще не оновлено!
4
Злив коштів (Drain)
Рекурсивний цикл повторюється, доки весь баланс вичерпано

The DAO (2016): $60 млн ETH вкрадено через reentrancy. Наслідок: хард-форк Ethereum на ETH та ETC. OWASP: 12.7% усіх експлойтів.

Захист від повторного входу (Reentrancy)

✅
Перевірки-ефекти-взаємодії (Checks-Effects-Interactions)
Спочатку перевірити умови, потім оновити стан, і лише тоді — зовнішній виклик
🔒
ReentrancyGuard (OpenZeppelin)
Mutex lock: блокує повторний вхід у функцію до завершення поточного виклику
📥
Витягування замість надсилання (Pull-over-Push)
Контракт записує суму, отримувач сам ініціює виведення — усуває рекурсію

Curve Finance (2023): reentrancy через вразливість компілятора Vyper — $60 млн. Вразливість може бути не лише у контракті, а й у інструментах.

Контроль доступу (Access Control)

Найдорожча категорія вразливостей: $953.2 млн збитків (OWASP 2025)

🔓 Проблема: критичні функції без обмежень — будь-хто може викликати адмін-операції
💥 Parity Wallet ($150 млн, 2017): devops199 «випадково» став власником бібліотеки та знищив її. 587 гаманців заморожені назавжди
🛡️ Захист: OpenZeppelin AccessControl (RBAC), таймлоки (Timelocks) 24-48 год, мультипідпис для адмін-функцій
📏 Принцип мінімальних привілеїв (Least Privilege): кожна роль — лише необхідні функції

Переповнення цілого числа (Integer Overflow)

💥
Переповнення (Overflow)
uint8: 255 + 1 = 0 (обгортання)
BEC Token (2018): мільярди токенів з нічого
До Solidity 0.8 — без перевірок
SafeMath від OpenZeppelin як захист
📉
Cetus ($223 млн, травень 2025)
DEX на блокчейні Sui (не Ethereum!)
Помилка у математиці ліквідності
Переповнення у граничних значеннях
Проблема НЕ специфічна для Solidity

Solidity 0.8+ (2020): автоматична перевірка overflow/underflow (revert). Але тисячі старих контрактів з мільярдами TVL — без захисту.

Формальна верифікація (Formal Verification)

📐 Що це? — математичний доказ коректності для ВСІХ можливих станів, не лише тестових сценаріїв
🔬 Certora Prover — інваріанти: «сума балансів = загальна кількість токенів», «лише адмін змінює параметр X»
🧮 K Framework, Halmos — формальна семантика EVM, символічне тестування для Solidity
⚖️ Обмеження: дорого ($100K+), довго (місяці), потребує коректної специфікації

Аудит знаходить відомі патерни. Формальна верифікація доводить відсутність цілих класів помилок. Найкращий підхід: автоматизовані інструменти + ручний аудит + Bug Bounty + формальна верифікація.
