Ланцюжок зберігання доказів (Chain of Custody)

Документування кожного кроку роботи з доказом

📋Документація — хто, коли, що робив з доказом на кожному кроці
🔒Цілісність — SHA-256 хеш оригіналу та копії повинні збігатися
🔄Передача — кожна передача фіксується: дата, час, від кого, кому
⚖️Порушення — зробить доказ недопустимим у суді

Порядок волатильності (Order of Volatility)

Збирай від найбільш волатильного

1
RAM
Процеси, з'єднання, ключі шифрування, fileless malware
2
Підкачка/Тимчасові (Swap/Temp)
Тимчасові файли з даними з RAM
3
Диск (Disk)
Файлова система, логи, deleted files, registry
4
Журнали/Резервні копії (Logs/Backup)
SIEM, мережеві пристрої, хмара, архіви

Вимкнення комп'ютера = втрата RAM. Спочатку дамп пам'яті, потім вимкнення та imaging диску.

Криміналістичне копіювання (Forensic Imaging)

🔧
Блокувальник запису (Write Blocker)
Апаратний пристрій: запобігає запису на оригінальний носій
💾
Побітова копія (Bit-for-bit Copy)
FTK Imager, dd: повна копія включно з видаленими областями
#️⃣
Верифікація хешу (Hash Verification)
SHA-256 оригіналу = SHA-256 копії = доказ цілісності
🧠
Дамп пам'яті (Memory Dump)
Volatility Framework для аналізу RAM: шкідливе ПЗ, ключі, з'єднання

Що шукаємо?

🦠Артефакти шкідливого ПЗ (Malware Artifacts) — виконувані файли, механізми закріплення, конфігурації C2
📊Журнали (Logs) — Windows Events, auth logs, web server logs, firewall
🗑️Видалені файли (Deleted Files) — відновлення видалених файлів через carving
🕐Часові мітки (Timestamps) — MACB (Modified, Accessed, Changed, Born) для хронології

Інструменти forensic imaging

Професійні засоби створення криміналістичних копій

💾
FTK Imager
Безкоштовний. Створення E01/DD образів, preview файлів, hash verification, memory capture
🐧
dc3dd / dcfldd
Linux CLI: покращений dd з вбудованим хешуванням, split output, progress bar
🔧
Tableau / Falcon
Апаратні write-blockers + imaging станції. Швидкість до 25 GB/хв, автоматичне хешування
☁️
KAPE / Velociraptor
Тріажний збір артефактів без повного imaging. Ідеально для remote та enterprise

Пріоритет волатильних даних

Що збирати НЕГАЙНО до вимкнення системи

1
Мережеві з'єднання
netstat -anob: активні C2 сесії, lateral movement, DNS requests
2
Запущені процеси
tasklist, Process Explorer: malware PID, parent-child relations, command line
3
RAM dump
WinPmem, Magnet RAM Capture: повний дамп оперативної пам'яті для Volatility
4
Активні сесії користувачів
query user, who: активні сесії, RDP-з'єднання, заплановані задачі

Порядок критичний: кожна дія на живій системі змінює пам'ять. Фіксуйте все ДО containment.

Форма ланцюжка зберігання (Chain of Custody)

Обов'язкові поля документування доказу

📋Ідентифікатор справи / доказу (Case ID / Evidence ID) — унікальний ідентифікатор справи та кожного окремого доказу
📅Дата/час збору — точний час з таймзоною, фіксація при вилученні
👤Хто зібрав — ПІБ, посада, підпис аналітика, який вилучив доказ
#️⃣Hash оригіналу — SHA-256 обчислений на місці збору, до будь-яких маніпуляцій
🔄Журнал передачі — кожна передача: від кого → кому, дата, час, причина, підписи обох сторін
🔒Умови зберігання — опис сейфу/сховища, контроль доступу, антистатична упаковка

Ключові висновки

1️⃣Chain of custody — документуй кожен крок, інакше доказ недопустимий
2️⃣Volatility first — RAM → Swap → Disk → Logs
3️⃣Write blocker — НІКОЛИ не працюй з оригіналом без захисту від запису
4️⃣Hash verification — SHA-256 підтверджує цілісність forensic image
