Оцінка серйозності 0.0 — 10.0

Базова оцінка CVSS (Base Score)

Складові оцінки

🌐 Вектор атаки (Attack Vector) — Network / Adjacent / Local / Physical
🧩 Складність атаки (Attack Complexity) — Low (тривіально) / High (потрібні умови)
🔑 Необхідні привілеї (Privileges Required) — None / Low / High
👤 Взаємодія користувача (User Interaction) — None (автоматично) / Required (клік)
💥 Вплив на CIA — Конфіденційність, Цілісність, Доступність: None/Low/High

SQLi в API банку: AV:N, AC:L, PR:N, UI:N, C:H, I:H, A:H = CVSS 9.8 (Critical).

VM як compliance-функція

Регуляторні вимоги PCI DSS

📋 Req 6.1 — ідентифікація вразливостей безпеки у всіх системах в PCI DSS scope
🔧 Req 6.2 — своєчасне встановлення критичних патчів (протягом 30 днів)
🔍 Req 11.2 — щоквартальне сканування на вразливості (ASV-сканування)
🛡️ Req 11.3 — щорічний тест на проникнення (пентест)

Штрафи за невідповідність PCI DSS — до $100 000/місяць. Equifax 2017: невиправлена вразливість → 147 млн скомпрометованих записів.

Обмеження CVSS + EPSS

Чому CVSS недостатній для пріоритизації

⚠️
Проблема CVSS
IDOR (CVSS 6.5) у публічному API банку може бути небезпечнішим за RCE (CVSS 9.8) в ізольованій системі
📈
EPSS
Exploit Prediction Scoring System — оцінює ймовірність реальної експлуатації вразливості (0-100%)
🏦
Критичність активу
Tier-1: платіжні системи. Tier-2: внутрішні інструменти. Контекст визначає реальний ризик
🧠
Threat Intelligence
Чи існує відомий експлойт? Чи активно використовується? Інтеграція з CTI-фідами

Формула пріоритизації: CVSS + EPSS + критичність активу + threat intelligence = ризик-орієнтований підхід.

Компенсуючі контролі для legacy-систем

Коли патчинг неможливий

🛡️ Virtual patching (WAF) — блокування відомих шаблонів експлуатації без зміни коду
🔒 Мережева сегментація — ізоляція вразливих систем (COBOL-ядро, legacy без вихідного коду)
📡 Посилений моніторинг (IDS/IPS) — виявлення спроб експлуатації в реальному часі
🔑 Додаткова автентифікація — MFA, обмеження доступу до вразливих компонентів

PCI DSS дозволяє compensating controls за умови документування, щорічного перегляду та еквівалентного рівня безпеки. Це тимчасовий захід — плануйте модернізацію.

Bug Bounty у FinTech

Безперервне тестування тисячами дослідників

🏦 Учасники: PayPal, Mastercard, Goldman Sachs, monobank
💰 Винагороди: $100 (low) — $50,000+ (critical) за вразливість
📋 Обсяг (Scope): чітко визначено що можна тестувати, відповідальне розкриття
🔧 Платформи: HackerOne, Bugcrowd, Intigriti

Bug bounty доповнює пентест: постійний процес vs періодичний, тисячі очей vs одна команда.

CVSS v3.1 Calculator: покроковий розбір

Приклад: SQL Injection у API платежів

🌐 Attack Vector: Network (N) — атака через інтернет, без фізичного доступу
🧩 Attack Complexity: Low (L) — SQLi тривіально експлуатується через sqlmap
🔑 Privileges Required: None (N) — неавтентифікований доступ до endpoint
👤 User Interaction: None (N) — жодна дія жертви не потрібна
💥 CIA: High/High/High — читання даних, модифікація записів, DoS можливий

Результат: CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H = 9.8 Critical. SLA: hotfix за 24 години.

Життєвий цикл вразливості

Від виявлення до закриття

1
Виявлення (Discovery)
Сканер, пентест, bug bounty, code review, інцидент
2
Тріаж (Triage)
Підтвердження, CVSS-оцінка, визначення пріоритету, присвоєння власника
3
Виправлення (Remediation)
Code fix, virtual patching (WAF), оновлення залежностей, конфігураційні зміни
4
Верифікація (Verification)
Re-testing: PoC більше не працює, regression test пройдено
5
Закриття та метрики
Закриття тікету, розрахунок MTTR, засвоєні уроки (lessons learned), оновлення сценарію реагування

Середній MTTR у фінансовому секторі: Critical 3 дні, High 15 днів, Medium 45 днів. Мета: зменшити вдвічі.

Процес відповідального розкриття (Responsible Disclosure)

Етичне розкриття вразливостей

1
Виявлення
Дослідник знаходить вразливість у рамках scope (або випадково)
2
Звіт вендору
Конфіденційне повідомлення через security@, bug bounty платформу або security.txt
3
Координація
Вендор підтверджує, оцінює CVSS, узгоджує таймлайн виправлення (зазвичай 90 днів)
4
Виправлення
Вендор випускає патч, CVE присвоюється через MITRE/CNA
5
Публікація
Публічне розкриття після патчу: advisory, блог-пост, CVE деталі. Винагорода дослідника

ISO 29147 (disclosure) + ISO 30111 (handling) — міжнародні стандарти процесу розкриття вразливостей.

🛡️

Ключові висновки

1️⃣ CVSS — стандарт оцінки: 9.0+ = Critical, fix за 24-72 год
2️⃣ Пріоритизація — CVSS + бізнес-контекст, не лише технічна оцінка
3️⃣ MTTR — ключова метрика, зменшуйте час від discovery до fix
4️⃣ Bug Bounty — безперервне доповнення до періодичних пентестів
