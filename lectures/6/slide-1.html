PCI DSS, НБУ, EBA посилаються на OWASP як базовий стандарт безпеки веб-додатків.

Top 10 (2021): A01-A05

🔓 A01: Порушення контролю доступу (Broken Access Control) — IDOR, горизонтальна ескалація, обхід авторизації API
🔐 A02: Криптографічні недоліки (Cryptographic Failures) — PAN без шифрування, MD5 для паролів, HTTP
💉 A03: Ін'єкції (Injection) — SQL, Command, LDAP-ін'єкції у фінансових системах
📐 A04: Небезпечне проєктування (Insecure Design) — архітектурні вразливості, відсутність моделювання загроз
⚙️ A05: Помилки конфігурації (Security Misconfiguration) — стандартні паролі, debug-сторінки, stack traces

Top 10 (2021): A06-A10

📦 A06: Вразливі компоненти (Vulnerable Components) — Log4Shell, Struts2 → Equifax (147M записів)
🪪 A07: Помилки автентифікації (Auth Failures) — credential stuffing без обмеження частоти, відсутність MFA
🔗 A08: Порушення цілісності (Integrity Failures) — атаки на ланцюг постачання, компрометовані CI/CD
📊 A09: Недоліки логування (Logging Failures) — невдалі логіни не логуються, логи не моніторяться
🌐 A10: SSRF — доступ до cloud metadata, внутрішніх сервісів банку

A01: Broken Access Control

#1 вразливість — критична для фінансів

🔢
IDOR
Зміна account_id=123 на account_id=456 → доступ до чужого рахунку
⬆️
Ескалація привілеїв (Privilege Escalation)
Касир отримує права менеджера через маніпуляцію параметром ролі
🔌
Обхід API (API Bypass)
Адмін-ендпоінт /api/admin/users доступний без перевірки ролі
📁
Обхід шляхів (Path Traversal)
../../../etc/passwd через ендпоінт завантаження

A01-A03 детально

Три найкритичніші категорії

🔓
A01: Порушення контролю доступу
94% додатків мають проблеми. IDOR, горизонтальна/вертикальна ескалація, помилки CORS, примусовий перегляд (force browsing) адмін-панелей
🔐
A02: Криптографічні недоліки
Передача PAN у відкритому вигляді, використання SHA-1/MD5, жорстко закодовані ключі, відсутність TLS 1.2+, слабка ентропія для токенів
💉
A03: Ін'єкції
SQL, NoSQL, OS Command, LDAP, XSS (тепер тут). ORM не панацея: HQL-ін'єкція, Sequelize raw-запити. Параметризовані запити обов'язкові

A01-A03 разом відповідають за понад 60% усіх критичних вразливостей у фінансових веб-додатках.

A04-A07 детально

Архітектура, конфігурація, компоненти

📐 A04: Небезпечне проєктування (Insecure Design) — відсутність моделювання загроз (threat modeling), бізнес-логіка без сценаріїв зловживань. Приклад: необмежена кількість спроб OTP у мобільному банкінгу
⚙️ A05: Помилки конфігурації (Security Misconfiguration) — стандартні облікові дані (admin/admin), відкриті S3 buckets, stack traces у production, увімкнені XML external entities
📦 A06: Вразливі компоненти (Vulnerable Components) — 80% коду — open source. SCA-інструменти: Dependabot, Snyk, OWASP Dependency-Check. SBOM (перелік компонентів ПЗ) як вимога регуляторів
🪪 A07: Помилки автентифікації (Auth Failures) — підстановка облікових даних (credential stuffing), відсутність MFA, слабке обмеження частоти запитів, фіксація сесії (session fixation)

Вразливості у FinTech контексті

Специфіка фінансових додатків

💳
Платіжні API
IDOR у транзакціях, race condition при переказах, маніпуляція сумою через параметр amount
🏦
Інтернет-банкінг
Session hijacking, XSS для крадіжки cookie, CSRF на форму переказу коштів
📱
Мобільний банкінг
Insecure local storage, відсутність cert pinning, reverse engineering APK/IPA
🔗
Відкритий банкінг (Open Banking API)
Помилки конфігурації OAuth2, порушення авторизації на рівні об'єктів, надмірне розкриття даних через PSD2 API

Середня вартість витоку у фінансовому секторі: $5.9M (2024). Найвищий показник серед усіх галузей після охорони здоров'я.

🛡️

Ключові висновки

1️⃣ Порушення контролю доступу (Broken Access Control) — загроза №1 для фінансових додатків
2️⃣ Вразливі компоненти (Vulnerable Components) — одна бібліотека = мільйони записів (Equifax)
3️⃣ Небезпечне проєктування (Insecure Design) — нова категорія, не виправити патчем
4️⃣ OWASP Top 10 — мінімальний стандарт, не повний список загроз
