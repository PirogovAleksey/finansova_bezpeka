A06:2025 Insecure Design + STRIDE

Безпека на етапі проєктування

📐
Insecure Design
Вразливості архітектури, які неможливо виправити патчем:
• Відсутність rate limiting на переказах
• Від'ємні суми (negative amount)
• Race condition при платежах
🛡️
STRIDE — моделювання загроз
Spoofing — підміна ідентичності
Tampering — модифікація даних
Repudiation — відмова від авторства
Info Disclosure — розкриття інформації
Denial of Service — відмова в обслуг.
Elevation of Privilege — підвищення привілеїв

Усунення вразливостей проєктування вимагає фундаментального перегляду архітектури та бізнес-логіки.

Фінансовий контекст OWASP Top 10:2025

Реальні інциденти 2024-2025

🔓 A01 (Access Control) — ByBit (лютий 2025): група Lazarus викрала $1.5B в Ethereum через порушення контролю доступу до гарячих гаманців
📦 A03 (Supply Chain) — CrowdStrike Falcon (2024): збій оновлення паралізував банки по всьому світу, збитки $5B+
📊 A09 (Logging) — OCC (2025): хакери шпигували за 103 регуляторами банків США понад рік через недоліки логування
⚙️ A02 (Misconfiguration) — помилки конфігурації хмарних сервісів залишаються причиною №1 витоків у фінансовому секторі
🪪 A07 (Auth) — credential stuffing на сторінці логіну банку, відсутність MFA для адміністраторів

64% фінансових установ зазнали кібератак у 2024 році (Contrast Security). Середня вартість витоку: $5.9M.

Top 10 (2025): A01-A05

🔓 A01: Порушення контролю доступу (Broken Access Control) — IDOR, ескалація привілеїв, обхід API, SSRF (консолідовано з A10:2021)
⚙️ A02: Помилки конфігурації (Security Misconfiguration) — стандартні паролі, відкриті S3 buckets, debug у production (піднялась з #5)
📦 A03: Збої ланцюга постачання ПЗ (Software Supply Chain Failures) — НОВА: вразливі залежності, компрометовані пакети, CI/CD атаки
🔐 A04: Криптографічні недоліки (Cryptographic Failures) — PAN без шифрування, MD5 для паролів, HTTP (опустилась з #2)
💉 A05: Ін'єкції (Injection) — SQL, Command, LDAP, XSS-ін'єкції у фінансових системах (опустилась з #3)

Top 10 (2025): A06-A10

📐 A06: Небезпечне проєктування (Insecure Design) — архітектурні вразливості, відсутність моделювання загроз (опустилась з #4)
🪪 A07: Помилки автентифікації (Authentication Failures) — credential stuffing без обмеження частоти, відсутність MFA
🔗 A08: Порушення цілісності ПЗ та даних (Software or Data Integrity Failures) — компрометовані оновлення, незахищені CI/CD пайплайни
📊 A09: Недоліки логування та оповіщення (Security Logging and Alerting Failures) — OCC 2025: шпигунство за регуляторами понад рік без виявлення
⚠️ A10: Некоректна обробка виняткових ситуацій (Mishandling of Exceptional Conditions) — НОВА: збої, витоки через необроблені помилки

A01-A03:2025 детально

Три найкритичніші категорії

🔓
A01: Порушення контролю доступу
Тепер включає SSRF. IDOR, ескалація привілеїв, помилки CORS, обхід API. ByBit 2025: $1.5B вкрадено через доступ до гарячих гаманців
⚙️
A02: Помилки конфігурації
Піднялась з #5. Стандартні облікові дані, відкриті S3 buckets, stack traces у production, надмірні дозволи у хмарних IAM-ролях
📦
A03: Збої ланцюга постачання ПЗ
НОВА категорія. CrowdStrike Falcon 2024: $5B збитків. Вразливі залежності, компрометовані пакети, dependency confusion, XZ Utils backdoor

A01-A03:2025 відображають головні ризики сучасності: контроль доступу, хмарні конфігурації та ланцюги постачання ПЗ.

A04-A07:2025 детально

Криптографія, ін'єкції, проєктування, автентифікація

🔐 A04: Криптографічні недоліки (Cryptographic Failures) — опустилась з #2. PAN у відкритому вигляді, SHA-1/MD5, жорстко закодовані ключі, відсутність TLS 1.2+, слабка ентропія токенів
💉 A05: Ін'єкції (Injection) — опустилась з #3. SQL, NoSQL, OS Command, LDAP, XSS. ORM не панацея: HQL-ін'єкція, Sequelize raw-запити
📐 A06: Небезпечне проєктування (Insecure Design) — відсутність моделювання загроз, бізнес-логіка без сценаріїв зловживань. Приклад: необмежена кількість спроб OTP
🪪 A07: Помилки автентифікації (Authentication Failures) — підстановка облікових даних (credential stuffing), відсутність MFA, слабке обмеження частоти запитів, фіксація сесії

Вразливості у FinTech контексті

Специфіка фінансових додатків

💳
Платіжні API
IDOR у транзакціях, стан гонки (race condition) при переказах, маніпуляція сумою через параметр amount
🏦
Інтернет-банкінг
Перехоплення сесії (Session hijacking), XSS для крадіжки cookie, CSRF на форму переказу коштів
📱
Мобільний банкінг
Незахищене локальне сховище, відсутність закріплення сертифіката (cert pinning), зворотна розробка APK/IPA
🔗
Відкритий банкінг (Open Banking API)
Помилки конфігурації OAuth2, порушення авторизації на рівні об'єктів, надмірне розкриття даних через PSD2 API

Середня вартість витоку у фінансовому секторі: $5.9M (2024). Найвищий показник серед усіх галузей після охорони здоров'я.
