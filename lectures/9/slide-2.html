ML для виявлення шахрайства

Конструювання ознак (feature engineering) — 6 категорій

💰 Ознаки суми (Amount) — транзакція / середня клієнта, близькість до порогів звітності, круглі суми
⏱️ Швидкість (Velocity) — кількість транзакцій за 5 хв / годину / добу (ознака клонованої картки)
📍 Географічні (Geo) — impossible travel, невідповідність IP-геолокації, high-risk країни
🕐 Часові (Temporal) — покупка о 3 AM для клієнта з активністю до 22:00, нетипові дні
🏪 Ознаки продавця (Merchant) — high-risk MCC: азартні ігри, крипто-біржі, подарункові сертифікати
📱 Ознаки пристрою (Device) — новий пристрій, зміна OS/браузера, VPN/Tor, device fingerprint

Конструювання ознак (Feature Engineering) для транзакцій

📊
Агрегатні
Сума/кількість транзакцій за 1h, 24h, 7d. Середня сума, max, stddev
🌍
Геопросторові
Відстань від попередньої транзакції, країна ризику, impossible travel flag
🔗
Графові
Мережа зв'язків: спільні пристрої, IP, отримувачі. PageRank для ризику
⏱️
Поведінкові
Відхилення від базової лінії: час, категорія мерчанта, сума vs група колег

Якість ознак визначає 80% результату. Модель з 200+ ознак дає точність (precision) 95%+ при повноті (recall) 70%+.

Ансамблеві моделі (Ensemble Models)

🌲
Random Forest
Стійкість до шуму, інтерпретабельність важливості ознак (feature importance)
⚡
XGBoost
Висока точність, швидке передбачення (inference), лідер Kaggle fraud
🧠
Нейронна мережа (Neural Network)
Складні нелінійні патерни, потребує більше даних
🔗
Стекінг (Stacking)
Мета-модель комбінує RF + XGB + NN для кращого результату

Незбалансовані дані (imbalanced data): шахрайство <0.1% транзакцій. SMOTE, навчання з вартістю помилок (cost-sensitive learning), focal loss для балансування.

ML-конвеєр для виявлення шахрайства (Fraud Detection)

1
Прийом даних (Ingestion)
Kafka/Kinesis: потік транзакцій у реальному часі, 10K+ TPS
2
Сховище ознак (Feature Store)
Redis/DynamoDB: pre-computed ознаки клієнта за останні 1h/24h/30d
3
Оцінка (Scoring)
ML-модель генерує fraud score 0-1000 за <50ms (SageMaker/Vertex AI)
4
Рішення (Decision)
Rules engine: approve / review / decline на основі score + бізнес-правил
5
Зворотний зв'язок (Feedback Loop)
Результати розслідувань повертаються для перенавчання моделі щотижня

Передбачення у реальному часі (Real-time Inference)

⚡ <100ms — fraud score за мілісекунди для кожної транзакції
📦 Сховище ознак (Feature Store) — попередньо обчислені ознаки для швидкого передбачення
🔧 Стиснення моделей (Model compression) — обрізка (pruning), квантизація для edge-розгортання
📊 A/B тестування — чемпіон/претендент для оновлення моделей у production

AML Risk Scoring: Rules vs ML vs GNN

📋
Rule-based (legacy)
Пороги: сума > $10K
500+ статичних правил
FP: >95%
Нові схеми — місяці
🤖
ML Risk Scoring
XGBoost, нейромережі
Dynamic score 0-100
FP: 50-70%
Нові схеми — за дні
🕸️
GNN (графові)
Аналіз графу транзакцій
Message passing
FP: 30-50%
ING: +50% виявлення

GNN виявляють smurfing (розбиття сум), layering (ланцюжки переказів), fan-out/fan-in та shell company networks через аналіз мережі зв'язків між рахунками.

Виявлення дипфейків (Deepfake Detection) у KYC

1
Загроза
Deepfake-відео для обходу відеоверифікації (KYC). 62% організацій вже зіткнулися зі спробами (Gartner, 2024)
2
Перевірка живості (Liveness Detection)
AI-аналіз мікрорухів, текстури шкіри, відблисків у зіницях, пульсу через фотоплетизмографію
3
PAD
Presentation Attack Detection: фото на екрані, 3D-маски, deepfake в реальному часі
4
Багатошаровий (Multi-layer)
Документ + обличчя (face matching) + живість (liveness) + пристрій = надійна верифікація

Liveness Detection і PAD: 5 механізмів

👁️ Мікрорухи обличчя — мимовільне моргання, мікроекспресії, рух зіниць; deepfake відтворює з характерними артефактами
🎨 Текстура шкіри — пори, нерівності, зморшки на мікрорівні; при збільшенні deepfake не відтворює ідеально
❤️ rPPG — Remote Photoplethysmography — виявлення частоти серцебиття через мікрозміни кольору шкіри; deepfake не імітує
📐 3D Depth Analysis — інфрачервоні сенсори або структуроване світло для підтвердження тривимірності обличчя (захист від фото/екранів)
🛡️ PAD (Presentation Attack Detection) — виявлення конкретних підробок: фото на екрані, 3D-маски, deepfake real-time; стандарт ISO/IEC 30107

Матриця помилок (Confusion Matrix): Recall > Precision

⚠️
False Positive (FP)
Легітимна транзакція заблокована. $443 млн річних втрат банків США через відмову клієнтів (Javelin 2024)
❌
False Negative (FN)
Шахрайство пропущено. Прямі фінансові збитки, репутаційні втрати, регуляторні санкції
✅
Recall ≥ 90%
TP / (TP + FN). Обов'язковий показник у банкінзі — частка виявленого шахрайства
📈
AUC-ROC 0.95-0.99
Якість сучасних fraud-моделей. F-beta (β>1) надає більшої ваги Recall над Precision

У фінансах Recall пріоритетніший за Precision: краще перевірити 100 зайвих транзакцій (FP), ніж пропустити одну шахрайську (FN). Прийнятний Precision — навіть 30-40%.
