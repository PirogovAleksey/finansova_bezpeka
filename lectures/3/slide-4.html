Identity Lifecycle

Joiner → Mover → Leaver

🚪
Новий працівник (Joiner)
Новий працівник: автоматичне створення акаунтів з HR-системи (SAP → AD)
🔄
Переведення (Mover)
Зміна посади: старі дозволи ← відкликати, нові → надати
🚫
Звільнення (Leaver)
Звільнення: негайне блокування всіх акаунтів (SLA — хвилини)

Privilege creep: після 5 переміщень працівник має доступ до 5 різних відділів. Жоден не відкликали.

SSO та Federation

Один вхід — доступ до всіх систем

🔐 SAML 2.0 — XML-based SSO для корпоративних B2B-інтеграцій
🌐 OIDC Federation — сучасна альтернатива на базі OAuth 2.0
🔄 SCIM — автоматична синхронізація ідентичностей між системами
🏦 У банку — один логін для CRM, АБС, email, HR-портал, SWIFT

SCIM: HR деактивує запис → автоматично блокуються акаунти у всіх 15 підключених системах.

Розділення обов'язків (SoD)

Запобігання шахрайству через dual control

🔒
Статичне SoD
Конфліктуючі ролі заборонені
Створює ≠ схвалює
Розробник ≠ production
Визначається при призначенні ролі
👀
Динамічне SoD
Обмеження на рівні транзакцій
Переказ > 100K = 2 оператори
SWIFT: принцип 4-eyes
Перевіряється в runtime

Bangladesh Bank (2016): зловмисники обійшли SoD контролі — $81M вкрадено. SWIFT посилив вимоги dual authorization.

Periodic Access Review

Регулярна рекапітуляція доступів

📅 Щоквартально — менеджери переглядають доступи своїх команд
🔍 Orphaned accounts — виявлення акаунтів звільнених працівників
📊 Excessive privileges — виявлення та відкликання зайвих дозволів
📋 Compliance — PCI DSS Req 7, SOX, вимоги НБУ

Автоматизація: IAM-система формує список доступів → менеджер натискає Confirm/Revoke → зміни застосовуються автоматично.

Етапи Identity Lifecycle

Повний цикл управління цифровою ідентичністю

1
Створення облікового запису (Provisioning)
HR створює запис → автоматичне створення AD, email, доступ до АБС за шаблоном посади
2
Налаштування автентифікації (Authentication Setup)
Реєстрація MFA (TOTP, FIDO2), видача корпоративного сертифіката, підписання NDA
3
Управління доступом (Access Governance)
Щоквартальний перегляд дозволів, запити через ServiceNow з approval workflow
4
Зміна ролей (Role Changes / Mover)
Переведення → автоматичне відкликання старих + надання нових дозволів за шаблоном
5
Деактивація облікового запису протягом 30 хвилин, відкликання сертифікатів, архівація даних
Деактивація (Deprovisioning / Leaver)

SLA для deprovisioning у банку: максимум 30 хвилин після повідомлення HR. Orphaned accounts — критичний ризик PCI DSS.

Порівняння SSO-протоколів

Вибір протоколу для фінансової інфраструктури

📄
SAML 2.0
Формат: XML
Транспорт: HTTP Redirect/POST
Токен: Assertion
Для: корпоративний B2B
Зрілість: висока (2005+)
🔑
OIDC / OAuth 2.0
Формат: JSON/JWT
Транспорт: REST API
Токен: ID Token + Access Token
Для: веб/мобільні, API
Зрілість: сучасний (2014+)
🔐
Kerberos
Формат: бінарний
Транспорт: TCP/UDP
Токен: Ticket (TGT/TGS)
Для: Active Directory LAN
Зрілість: legacy (1988+)

Типовий банк: Kerberos для внутрішньої мережі + SAML для партнерів + OIDC для клієнтських додатків та Open Banking.

Архітектура PAM-рішення

Компоненти Privileged Access Management

🔒
Сховище паролів (Password Vault)
Централізоване зберігання root/admin паролів. AES-256 шифрування. Ніхто не знає пароль — лише vault
🖥️
Менеджер сесій (Session Manager)
Проксі для SSH/RDP. Запис відео-сесій. Keystroke logging. Real-time моніторинг команд
⏰
JIT/JEA Controller
Just-In-Time: доступ на 2 год за запитом. Just-Enough-Admin: мінімальні необхідні привілеї
🔄
Ротація облікових даних (Credential Rotation)
Автоматична зміна паролів після кожного check-in. Інтеграція з AD, DB, Linux, мережеве обладнання
$4.35M
середня вартість інциденту через привілейований доступ
90%
зниження ризику з впровадженням PAM

Ключові висновки

1️⃣ Identity Lifecycle — Joiner/Mover/Leaver з автоматизацією через SCIM
2️⃣ SSO + Federation — один вхід для всіх систем, SAML/OIDC
3️⃣ PAM — критичний — Vault, JIT, session recording для привілейованих
4️⃣ SoD + Access Review — dual control та регулярний перегляд дозволів
